## 검토 중인 구성

1. 사진 중심 구성: 넓은 흰 여백과 큰 착용 사진, 목적별 제품 안내, 색상 탐색, 제품과 최신 이야기. 참고 사이트의 사진 비중을 살리면서 히마와리 색상을 연결하는 추천안.
2. 제품 중심 구성: 흰 첫 화면에 가방을 크게 배치하고 색상을 고르며 제품을 살펴봄. 선택 동작은 명확하지만 생활 장면의 비중은 작아짐.
3. 색상 중심 구성: 서로 다른 제품색을 구역별로 배치해 탐색을 이끔. 색의 인상은 강하지만 사진 중심 구성보다 편집 밀도가 높아짐.

흰색 캔버스와 짙은 본문 글자를 공통으로 쓰고, 제품 사진에서 확인한 민트·연핑크·라벤더·머스터드·오렌지·네이비/그린을 사진·색상 선택·일부 안내 면에 연결하는 방안을 검토 중임. 색상 코드는 아직 확정하지 않았으며 제품 실물의 측색값으로 표현하지 않음.

- 브라우저 검증: 세 시안 각각 Chrome 156의 1440px·390px에서 사진 로딩과 화면 넘침 확인. 다섯 색상 모두 제품 ID·사진·상세 URL이 일치했고, 메뉴와 빈 장바구니의 열기·Escape 닫기가 동작함. 자동 비교 페이지의 모바일 폭 측정 일부는 전환 도중 수집됐으므로 직접 390px 캡처와 구분함.

# 승인한 수정 3안 적용

사용자가 수정한 3안의 전체 적용, 기존 기능 보존, PC·모바일 확인과 Git·Vercel 배포를 승인했습니다. 추가 승인을 요청하지 않고 기존 저장소에서 구현했습니다.

- 흰 바탕, 실제 제품 사진과 가방 색상 선택, 둥근 공통 메뉴·아이콘 버튼을 적용했습니다. 색상 선택은 운영 카탈로그를 함께 조회하며 사진·제품 ID·상세 링크를 대조합니다.
- 기존 대표 제품 설정, 상품 목록·검색·옵션, 장바구니·회원, 주문서·결제 수단, 영상·게임·문의, 이야기·RSS와 룩북 기능을 보존했습니다. 기존 영상은 첫 화면 아래로 이동했습니다. 가격·재고·회원/주문 데이터와 결제 설정은 바꾸지 않았습니다.
- Anime.js 4.5.0, daisyUI 5.7.50과 Tailwind 4.3.3을 프로젝트에 설치했습니다. reset 없이 접두사를 붙인 버튼 CSS를 빌드하고 필요한 사진 전환만 사용합니다. 글꼴·아이콘은 로컬 파일과 라이선스를 포함했습니다.
- 변경 전 테스트270개, 구현 후274개가 통과했습니다. 공개 화면용 빌드와 관리자 빌드가 성공했습니다. 관리자 빌드에서 드러난 기존 소스/산출물 차이는 이번 작업 범위 밖이므로 산출물을 포함하지 않았습니다.
- Chrome 320·390·768·1440px에서 화면·사진 비율·44px 색상 버튼을 확인했습니다. 색상 연속 선택, 사진 오류, 빈 목록, 조회 실패와 재시도, 동작 줄이기, 메뉴8개 링크·Escape·포커스, 회원·장바구니, 외부 스토어4곳, 검색, 상품 담기, 룩북 확대·다음·닫기와 주문서 진입을 검증했습니다. 실제 주문·결제·문의 제출은 하지 않았습니다. 로컬 Npay는 운영 도메인이 아니므로 origin 검증 제한이 있습니다.
- 독립 리뷰에서 뒤로 가기 복원 후 선택이 멈추는 문제를 찾아 재현한 뒤 수정했습니다. persisted lifecycle 재현과 실제 상세 → 뒤로 가기 → 색상 변경을 다시 확인했습니다. 리뷰의 해당 수정 판정은 `ship`이며 전체 기능 무결성을 무제한 보증하는 표현으로 쓰지 않습니다.
- 기존 이야기170편의 article SHA-256과 story/posts.json·feed.xml·lookbook/entries.json의 파일 해시는 원본과 같습니다. 최초 발행·수정 시각과 원래 배포 이력은 보존했습니다.
- Figma 승인 시안은 기존 편집 가능한 파일의 node11:2에 있습니다. 추가 디자인 문맥 조회는 계정 도구 호출 한도로 실패했으며, 실제 구현은 승인한 브라우저 시안과 Chrome 캡처로 검수했습니다.

구현 계획은 `docs/superpowers/plans/2026-10-30-home-redesign.md`이며 사진 출처·브라우저 캡처·테스트 원본은 `backups/home-redesign-2026-10-30/`에 있습니다. Git/Vercel 운영 반영의 최종 상태·정확한 SHA·READY 원본·실제 운영 확인은 같은 폴더의 `deployment-receipt.json`을 기준으로 합니다. 배포 대기와 완료를 혼동하지 않으며 운영 검증 후에만 완료로 알립니다.

# 구현 중 추가 요청

- 사용자가 첫 화면에 접속할 때마다 제품을 무작위로 보여 달라고 요청했습니다. 운영 카탈로그의 실제 제품군을 무작위로 선택하고 해당 모델의 현재 색상·사진·상세 링크를 연결했습니다. 다른 후보가 있으면 직전 모델은 제외합니다. 관리자 대표 제품 설정은 바꾸지 않았습니다.
