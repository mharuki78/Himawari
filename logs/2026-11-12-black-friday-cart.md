# 블랙 프라이데이 상품 수·상세·장바구니

- 날짜·시간대·담당: 2026-11-12, Asia/Seoul · Codex
- 작업 ID: black-friday-cart-20261112
- 사용자 요청: 행사 100개 제한 확대, 상품정보에서 전체 상세페이지 표시, 행사 상품 장바구니 담기 지원.
- 조사: 100개는 행사 품목 등록 제한이며 개별 행사 수량은 별도 상한이다. 현재 행사 주문은 한 상품만 허용하고 장바구니·회원 동기화가 행사 식별자를 보존하지 않는다. 기존 상품정보 주소는 전체 제품 상세 대신 행사 구매 카드만 표시한다.
- 구현 선택: 품목 등록은 1,000개로 확대한다. 기존 상세 템플릿과 장바구니를 확장하고 행사 식별자·가격을 모든 저장 경로에서 유지한다. 여러 행사 상품과 다른 일반 품목을 함께 주문할 수 있도록 서버가 할인·재고·행사 할당을 품목별 검증한다. 기존 행사 주문의 쿠폰·Npay 제한은 유지한다. 운영 주문·결제나 고객 개인정보를 사용하지 않고 독립 가상 데이터로 검증한다.
- 설계·작업 범위: `docs/superpowers/plans/2026-11-12-black-friday-cart.md`.
- 완료 상태는 아래 운영 확인과 최종 receipt를 기준으로 한다.

## 구현·배포 전 확인

- 행사 품목 한도 1,000개와 관리 API 요청 한도를 함께 반영했다. 실제 행사 설정 값·상품 가격·재고·일정·배너를 변경하는 운영 API 호출은 하지 않았다.
- 전체 상품 상세 템플릿을 행사 URL에 재사용했다. 원래 상세 사진·설명·사양·리뷰 영역을 표시하며 확인된 행사 옵션·가격·수량·구조화 데이터를 적용한다. 최초 확인 실패·행사 종료·화면 복귀 때는 행사 가격/구매 동작/Offer 구조화 데이터를 제거하거나 재확인한다.
- 장바구니 로컬 저장·복원·회원 동기화·주문서에 행사 식별자와 확정 단가를 유지한다. 일반 품목과 함께 주문할 수 있고 각 상품의 할인·수량·재고 예약을 하나의 트랜잭션에서 검증한다. 과거 단일 행사 주문 요청도 호환한다.
- 독립 검토에서 발견한 옵션 이름을 통한 중복 재고 우회, 종료 상품이 다른 장바구니 수정까지 막는 현상, 회원 복원 후 Npay가 일반가로 연결되는 현상, 주문 완료 후 다른 기기의 잔여 상품이 사라지는 현상, 최초 상세 확인 실패 시 오래된 구조화 데이터가 남는 현상을 회귀 테스트와 함께 수정했다. 최종 서버·회원 작업 재검토 16개, 상세·브라우저 연결 재검토 21개가 통과했다.
- 최종 전체 테스트 378개와 관리자 빌드가 통과했다. 테스트의 sitemap 순서 변경은 전체 URL 내용의 일치를 대조한 뒤 원래 바이트로 복구했다.
- Chrome 157, PC 1440px·모바일 390px에서 행사 목록 담기, 전체 상세 확인, 새로고침 후 가격 유지, 일반 상품 포함 장바구니, 주문서와 가상 무통장 주문, 구매 품목만 제거하는 흐름을 확인했다. 합계146,000원·배송비0원·품목3개·예약3개를 실제 검증 함수와 독립 PGlite로 확인했다. 이 검증은 운영 주문·고객·결제를 사용하지 않았다.
- 관리자 화면에서 110개를 일괄 선택해 기존2개와 합계112개를 추가했고, 행사 종료 상태에서는 장바구니가 일반가로 바뀌지 않고 주문을 차단했다. 임시 테스트 서버·브라우저 근거는 `backups/black-friday-cart-2026-11-12/`에 보존한다. 초기에 검증 전용 SSR 번들 경로/상품 정렬 가정/래퍼 인자 순서를 수정한 뒤 위 전체 흐름을 재실행해 통과했다.
- 시각 검수에서 장바구니 안내 위로 상담 버튼이 겹쳐, 장바구니가 열린 동안만 숨기도록 보완했다. 기존 Figma 파일은 홈페이지3개 시안만 있어 해당 흐름의 설계 원본으로 간주하지 않고 기존 제품/장바구니 디자인을 유지했다.
- 최종 완료 기준은 정확한 커밋의 production READY와 운영 읽기 전용 확인 이후 `backups/black-friday-cart-2026-11-12/deployment-receipt.json`에 기록한다.

- 작업 파일33개만 담은 기능 커밋 `2f25372b18fa0ffc689319e356d88fa2858a1d16`를 동기화하고 Vercel production `dpl_HqCfZaRcQAhPJV4AiiJmJGnv3EWo` READY와 `himawari.co.kr` 연결을 확인했다. 완료 기록 후속 커밋의 배포 근거는 최종 receipt에서 관리한다.
