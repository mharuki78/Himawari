# 카카오페이 단건 결제

2026-10-01 승인 CID: `CT07417871`. 도메인: `https://himawari.co.kr`.

## 활성화 조건

1. [카카오페이 개발자센터](https://developers.kakaopay.com)의 해당 애플리케이션에 온라인 결제 사용 권한과 운영 CID가 연결되어 있어야 한다. 애플리케이션 ClientID와 CID의 연결 여부를 가맹점센터에서 확인한다.
2. 플랫폼 Web 도메인에 `https://himawari.co.kr`을 등록한다. 성공·취소·실패 콜백은 `/payment-return.html`이다.
3. Vercel himawari 프로젝트의 **Production** 환경에 `KAKAOPAY_SECRET_KEY`를 Secret key(prod)로 설정한다. `KAKAOPAY_CID=CT07417871`. 로그인용 `KAKAO_CLIENT_SECRET`이나 Secret key(dev), 테스트 CID를 사용하지 않는다. 인증키는 저장소·프론트엔드·로그·채팅에 남기지 않는다.
4. DB 스냅샷 확보 후 검증된 `scripts/migrate-kakaopay.mjs`를 직접 연결로 적용한다. 스키마는 별도 `kakaopay_payments` 테이블만 추가한다.
5. 운영 인증키와 CID 권한으로 결제 준비 응답을 검증한 뒤 `KAKAOPAY_ENABLED=true`로 설정하고 재배포한다. 실제 결제·취소는 가맹점 운영자가 확인한다. 키만 저장해도 기존 배포의 환경에는 적용되지 않으므로 재배포가 필요하다.

인증키·권한이 준비되지 않으면 버튼을 공개하지 않는다. `/api/kakaopay/config`는 enabled만 반환하며 인증키·CID 상세 설정을 노출하지 않는다.

승인 이메일에 안내된 파트너어드민 정보제공 동의와 권한 요청은 정산·운영 화면의 접근 절차이며, 개발자센터 결제 인증키와 별개다. 사용자가 직접 정보제공 동의와 가맹점센터 권한 요청을 완료한다.

## 주문·결제 흐름

- 주문서에서 배송정보·약관 동의 후 카카오페이를 선택한다. 서버가 카탈로그 가격·옵션·배송비·유효 쿠폰을 다시 검증해 주문을 생성한다. 클라이언트 금액은 신뢰하지 않는다.
- `ready` 응답의 TID와 PC·모바일 URL을 서버에 보관한다. 카카오에 보내는 partner_user_id는 주문별 불투명 식별자이며 이메일·전화번호·이름을 보내지 않는다. 상품 비과세 금액은 0, 부가세는 카카오페이 자동 계산을 사용한다.
- 고정 도메인 콜백, 서명된 주문 상태 토큰, 같은 출처 POST로 승인한다. 결제 결과 페이지는 쿼리의 pg_token을 즉시 주소창에서 제거하며 외부 분석 스크립트를 사용하지 않는다.
- 실제 결제 조회를 먼저 수행해 승인 응답 유실을 복구한다. 승인 직전에 재고를 예약하며, 서버에 저장된 CID·TID·주문번호·사용자 식별자·금액이 승인 응답과 모두 일치해야 결제 완료로 반영한다.
- 승인은 작업 잠금으로 직렬화하고 DB에서 주문·결제·이벤트를 함께 갱신한다. 쿠폰은 주문 생성 시 기존 원자적 사용 검증을 따른다. 미결제 종료는 쿠폰과 재고 예약을 함께 복원한다.
- 결과가 불확실하면 주문을 성공·미결제로 단정하지 않고 예약을 유지한다. 같은 결과 페이지에서 다시 조회하거나 고객센터에서 주문번호를 확인한다. 확정된 취소·실패 또는 아직 승인 요청을 하지 않은 주문만 미결제로 종료한다.
- 승인 완료 이후에만 장바구니에서 해당 구매 수량을 제거한다. 결제 준비·실패 단계에서는 장바구니를 비우지 않는다.
- 관리자도 미승인 카카오페이 주문을 수동으로 주문 확인·배송 단계로 바꿀 수 없다. 취소·환불 완료는 카카오페이 전액 취소 확인 이후에만 저장한다. 부분 취소된 결제는 자동으로 전액 환불 완료로 표시하지 않고 별도 확인한다.

## 운영 복구

`approving`이나 `cancelling` 상태에서는 새 주문으로 다시 결제하지 말고 동일 주문의 결과를 조회한다. 잠금은 60초, API 요청 제한은 15초다. 승인 성공 후 DB 저장 실패도 동일 TID 조회로 복구한다. 카카오페이 취소 성공 후 주문 수정 충돌 시 실제 취소 결과는 보존하며, 최신 주문 상태로 관리자 저장을 재시도한다.

결제 준비 후 30분이 지난 미결제 주문은 새 승인 요청을 거부한다. 자동으로 재고·쿠폰을 풀지 않으며 관리자 취소 시 공급자의 미결제 결과를 확인해 종료한다. PG 호출 원문·카드 정보는 저장하지 않는다. 알림은 실제 승인 확정 후 기존 주문 알림 큐를 통해 보낸다.
