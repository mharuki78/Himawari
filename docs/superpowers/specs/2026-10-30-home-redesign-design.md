# Himawari 홈페이지 리모델링 설계

상태: 2026-10-30 사용자가 수정한 3안의 전체 적용, 기존 기능 보존, PC·모바일 검증, Git push와 Vercel 운영 배포를 승인했습니다. 구현 중입니다.

## 목적과 근거

사용자는 파리크라상 홈페이지의 사진 중심 구성, 애플을 연상시키는 간결한 UI, 흰색 바탕과 실제 히마와리 가방의 다양한 색을 원합니다. 기존의 큰 짙은 녹색 면과 비슷한 큰 제목이 반복되는 구성을 새로 설계합니다. 방문자가 좋아하는 색과 가방의 실제 모습을 먼저 살펴보고 제품 정보와 구매 화면으로 이동하게 합니다.

2026-10-30 비교 시안은 공식 카탈로그 사진을 사용했습니다. 세 안의 PC 1440px·모바일 390px 화면과 기본 동작을 Chrome에서 확인했습니다. 3안 선택 근거는 로컬 비교 세션의 실제 `choice=colour` 클릭 기록입니다. 채팅으로 추가 의견이 오면 그 내용을 우선합니다.

## 범위

- 홈페이지를 3안의 시각 언어와 탐색 순서로 리모델링합니다.
- 공통 헤더·메뉴·아이콘·버튼·푸터에 같은 규칙을 적용합니다. 공통 색 토큰을 바꿀 때는 제품·브랜드·이야기·룩북·회원·장바구니·주문·문의 등 영향을 받는 공개 화면도 함께 맞춥니다.
- 제품별 상세 정보, 제품 링크, 가격·할인·재고, 회원 인증, 구매·결제·배송·쿠폰, 관리자 기능과 데이터는 기존 동작을 유지합니다. 주문이나 결제는 실제로 실행하지 않고 검증합니다.
- 이야기 자동발행이 사용하는 목록·홈 최신 이야기·메타데이터·RSS 연결과 승인된 글·사진·발행 근거를 보존합니다.
- 새 이야기나 룩북을 만들거나 과거 미발행일을 채우는 작업은 이번 디자인 변경에 포함하지 않습니다.

## 첫 화면과 정보 순서

1. **헤더:** 원본 로고, 주요 메뉴, 검색·계정·장바구니 아이콘. 화면에 간결하게 보이는 주요 메뉴 외의 기존 가방 찾기·가이드북·게임·문의·외부 스토어도 접근 가능한 메뉴에 남깁니다. 모바일은 펼침 메뉴를 쓰고 Escape·포커스 복귀를 제공합니다.
2. **컬러 탐색:** 왼쪽에 짧은 한국어 제목과 색상 버튼, 선택한 모델·색상 및 상세 이동 링크를 둡니다. 오른쪽에는 해당 색상의 실제 제품 사진을 크게 보여줍니다. 모바일은 제목·색상 선택·사진 순서로 쌓습니다.
3. **제품 탐색:** 기존 운영 카탈로그와 대표 제품 설정을 재사용합니다. 컬러 탐색을 추가하기 위해 관리자의 대표 제품 설정이나 제품 순위를 덮어쓰지 않습니다. 제품 목록과 더 보기 기능을 유지합니다.
4. **착용 모습·영상·브랜드:** 기존에 승인된 자료를 새 사진 중심 구성에 맞게 배치합니다. 사진과 카피의 내용이 맞도록 고르고, AI 연출 여부와 실제 제품 사진의 구분을 보존합니다.
5. **최신 이야기:** 자동발행으로 갱신되는 최신 3편을 표시하고 전체 이야기와 RSS로 연결합니다.
6. **도움과 문의:** 게임·가방 찾기·가이드북·FAQ·비공개 문의로 가는 기존 동선을 유지하되 큰 제목과 장식 면의 반복을 줄입니다.
7. **푸터:** 법적·사업자 정보와 고정 문구, 실제 외부 채널 링크를 보존합니다.

## 제품과 색상의 연결

2026-10-30 구현 중 사용자가 첫 화면의 접속별 제품 무작위 표시, 이야기 연필 효과 제거와 상단 ‘더보기’ 제거를 요청했습니다. 이 추가 요청이 아래 초기 No.0422 고정 선택보다 우선합니다. 운영 카탈로그에서 유효한 공식 이미지·모델·색상이 확인된 제품군을 무작위로 고르고 그 모델의 현재 색상을 연결합니다. 가능한 경우 바로 이전 접속의 모델은 제외합니다. 색상이 많으면 모바일 색상 바 안에서 가로로 이동하며 페이지 전체가 넘치지 않게 합니다. 상단의 기존 메뉴8개는 모두 직접 나열하고 좁은 화면에서는 기존 모바일 펼침 메뉴에 모두 표시합니다. 이야기의 연필 포인터·잔상 캔버스·이벤트는 제거합니다.

- 시안의 출발 모델은 실제 No.0422이며 민트·핑크·블루·옐로우·퍼플을 실제 제품 ID에 연결했습니다. 이는 초기 편집 선택이며 해당 모델의 관리자 설정을 바꾼다는 뜻이 아닙니다.
- 운영에서는 기존 공개 제품 데이터와 옵션 정보를 사용합니다. 모델·색상·제품 ID·사진·제품 상세 URL을 함께 관리해 서로 어긋나지 않게 합니다. 확인되지 않은 색상 옵션이나 수납·소재·효능을 만들지 않습니다.
- 색을 고를 때 사진, 선택 표시, 색 이름, 상세 링크가 함께 바뀝니다. 첫 화면 사진 크기는 예약해 레이아웃이 흔들리지 않게 합니다.
- 제품 사진은 `contain` 등 원본 비율을 보존하는 방법으로 표시합니다. 손잡이·로고·포켓·가방 바닥을 자르거나 CSS로 제품 색을 바꾸지 않습니다. 큰 착용 사진도 가방의 전체 구조가 가려지지 않게 배치합니다.
- 특정 제품이 공개 목록에서 사라지거나 데이터가 없으면 첫 번째 유효한 제품 또는 기존 제품 보기 링크를 제공합니다. 로딩·오류·빈 결과를 숨기지 않으며 가짜 사진·가격·재고를 채우지 않습니다.

## 시각 규칙

- 바탕은 흰색 `#FFFFFF`, 본문과 주요 행동은 대비가 충분한 짙은 색을 사용합니다.
- 민트·연핑크·라벤더·머스터드·오렌지·네이비/그린 배색을 실제 제품 사진과 연결합니다. 여러 색을 쓴다는 이유로 버튼마다 행동 색을 바꾸지 않습니다. 파스텔은 주로 색상 선택과 일부 사진·안내 면에 쓰고 작은 본문은 짙은 글자로 유지합니다.
- 시안의 색 코드는 화면용 편집 값이며 제품 실물의 측색값으로 표시하지 않습니다.
- 원본 로고의 형태와 색을 보존합니다. 한국어는 기존 브랜드에 맞는 읽기 쉬운 글꼴을 사용하고 의미 단위로 줄바꿈합니다. 과장된 비유와 번역투 문구를 쓰지 않습니다.
- 아이콘은 애플의 간결한 느낌을 웹에서 사용할 수 있는 Phosphor 계열의 일관된 선·크기로 구현합니다. Apple 로고나 SF Symbols 원본을 사이트 자산으로 추출하지 않습니다.
- 사용자 추가 의견에 따라 메뉴는 아이콘과 글자를 함께 쓰는 둥근 캡슐로, 검색·계정·장바구니·메뉴는 둥근 아이콘 버튼으로 구성합니다. 주요 상세 이동은 아이콘과 문구가 함께 있는 명확한 pill 버튼으로 표시합니다.
- 색상 선택은 밝은 회색 캡슐 안에 실제 제품 색을 놓고 선택한 색에 테두리와 체크를 함께 표시합니다. 전체 가방·가방 찾기·룩북·이야기는 제품 배색을 활용한 앱 아이콘 형태의 바로가기로 연결합니다. 버튼과 텍스트의 의미를 아이콘만으로 숨기지 않습니다.
- 모바일의 아이콘 버튼과 색상 선택 영역은 가로 44px 이상을 확보하고 작은 라벨은 12px 이상으로 유지합니다. 제품 사진의 원본 비율과 흰 바탕은 유지합니다.
- 큰 제목은 화면당 하나가 중심이 되게 하고, 카드·둥근 면·그림자를 반복 장식으로 쓰지 않습니다. 사진·여백·크기 차이로 구역을 구분합니다.

## 구현 선택

- 기존 정적 HTML/CSS/JavaScript, 서버 API와 npm 잠금 파일을 이어 씁니다. React 등 다른 프레임워크로 옮기지 않습니다.
- Anime.js는 필요한 색상 전환·메뉴 상태 등 제한된 모션에 사용합니다. 반복 부유 효과나 스크롤 강제 이동을 만들지 않습니다. reduced-motion에서는 즉시 상태 변화 또는 짧은 페이드로 대체하고 리스너·인스턴스를 정리합니다.
- daisyUI와 필요한 Tailwind 빌드 도구는 프로젝트에 설치해 로컬 CSS를 생성합니다. 전체 reset이나 기본 테마가 기존 구매·관리 화면을 덮어쓰지 않게 범위를 정합니다. 버튼·메뉴·선택 상태를 히마와리의 새 시각 규칙에 맞춥니다.
- 두 라이브러리의 버전과 설정은 실제 설치 시점의 공식 문서로 확인합니다. 비교용 시안은 정적 HTML이며 이를 운영 구매 기능의 구현으로 간주하지 않습니다.
- `data-home-stories`, 제품 렌더러, 구매·회원·메뉴의 기존 연결 지점을 조사해 재사용합니다. 새 정적 샘플이나 별도 복제 데이터로 대체하지 않습니다.
- 공통 CSS 변경은 홈 전용 규칙과 공통 토큰을 구분합니다. 관리자 화면은 명시적으로 새 브랜드 디자인을 적용하지 않으며 공통 변경에 따른 기능·대비 회귀를 막습니다.
- 로컬 비교 세션과 그 접근 키는 Git·Vercel 업로드에서 제외합니다.

## 검증과 완료 기준

- 기존 관련 테스트와 전체 테스트, 정적 빌드, Git diff 검사를 실행합니다.
- Chrome에서 320·390·768·1440px와 대표 데스크톱 폭을 확인합니다. 가로 넘침, 한국어 제목 잘림, 사진 로딩과 원본 비율, 선택 색·제품 링크의 일치를 검사합니다.
- 키보드 메뉴·검색·색상 선택·장바구니·회원 화면·Escape·포커스 복귀, 모바일 제품 탐색, 기존 주문 진입·쿠폰 등 바뀌는 경로를 확인합니다. 실제 주문·결제나 계정 설정 변경은 하지 않습니다.
- reduced-motion, 로딩·오류·빈 상태, JS 로딩 전 주요 링크, 텍스트·버튼·포커스 대비를 확인합니다.
- 이야기 최신 목록과 RSS 연결을 확인하고 글 본문·승인 사진·발행 시각에 불필요한 변경이 없는지 대조합니다.
- 최종 디자인 리뷰 후 실제 구현으로 `DESIGN.md`와 필요한 디자인 기록을 갱신합니다. 전면 리모델링 완료를 비교 시안 제작 완료와 혼동하지 않습니다.
- Git·Vercel 반영 단계에서는 이번 작업 파일만 포함하고 해당 커밋의 production READY 및 실제 운영 사이트 PC·모바일 결과를 확인합니다. 운영 반영 전까지 비교 시안이라는 상태를 명확히 유지합니다.

## 승인 후 다음 행동

이 설계의 범위를 확인한 뒤 구현 계획을 작성합니다. 세부 간격·색 농도·사진 배치·컴포넌트 구조는 위 조건 안에서 구현자가 결정하고, 실제 화면에서 발견한 문제는 별도 승인 요청 없이 고쳐 검증합니다. 사용자 승인과 구현자의 세부 선택은 작업 로그에서 구분합니다.
